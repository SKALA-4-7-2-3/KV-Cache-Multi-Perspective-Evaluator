## 수정 내용

1. **공개 TRL 사유 분리**: 원래 Review의 reason/checks는 보존한다. 알려진 내부 controller 진단은 별도 typed 표시 필드로 구분하여 공개 본문에는 다음 조건의 미확인 설명만 작성한다. 단계 변경·미확인 의미 반전·내부 진단 재출력은 반려한다.
2. **서지 정보의 정확한 검증**: 모든 TeX 참고문헌이 등록된 canonical 서지 형식과 일치하고 실제 PDF entry 전체가 같은 내용일 때만 해당 표시 범위를 메타데이터로 처리한다. 같은 줄이나 다음 줄의 추가 사실은 의미 감사에 남는다.
3. **TRL의 평가 권위 구분**: atomic text와 실제 report_quote가 모두 Review가 승인한 정확한 TRL 표시와 일치할 때 별도 governed registry에 기록한다. 이유·검증 환경·주변 사실과 공식 인증 주장은 계속 원문 감사 대상이다.
4. **모순 판정의 계약**: `contradicted`는 원문 인용과 명시적 반대 명제를 요구한다. 지원 이유와 모순 enum의 불일치는 최대 한 번 계약 보정 후에도 지속되면 미검사 오류로 종료한다. 이를 코드에서 supported로 바꾸지 않는다.
5. **구간 수정**: 모든 피드백 위치가 실제 본문과 연결되면 지정된 본문 구간만 JSON 패치로 반환하도록 한다. 선택하지 않은 본문·제목·검사 주석·문서 경계는 보존한다. 전체 원문을 계속 전달하고 적용 후 전체 형식·인용·TRL·시장 12개 항목을 검사한다. 위치가 하나라도 불명확하면 이유를 기록하고 기존 전체 문서 수정으로 전환한다.

## 실제 재개 준비와 보존한 기록

새 사용자 요청에 따라 Report 8을 한 번 명시적으로 개발 재개했다. 기존 자동 내용 평가 상한 3회와 과거 개발 재개 결과를 지우지 않았으며, 재개 전 `quality_attempt=7`, 완료 내용 평가 횟수 4를 유지했다.

이전 오류 피드백 중 19개 주장은 새 production guard로 정확한 서지·TRL 필드임을 확인해 별도 routing 기록에 남겼다. 원래 Judge 판정은 수정하지 않았다. 남은 실제 주장·감사 정보와 수동 원문 검토를 포함한 16개 요청이 10개 본문 구간을 지정한다. 성공했던 원문 독해 캐시 22개는 source identity와 연속된 원문 quote를 다시 검증하여 사용했다.

Report 호출 1회와 기본 모델 접근 확인 1회는 접근 오류로 실패했다. 이후 사용자의 모델 교체 요청에 따라 공식 문서의 최신·일반 모델 후보 7개를 짧은 요청으로 추가 확인했지만 모두 같은 오류였다. 이 호출들은 누적 사용량에 포함된다. 모델 목록 조회는 자료 전송 없는 별도 진단이며 평가 성적으로 세지 않는다. 최신 누적 수치는 JSON receipt에 기록했다. 실제 청구 금액이나 새 실행의 성능 수치가 아니다. 일곱 번째 한도 증액도 이전 사용량을 보존하여 기록했다.

OpenAI의 [공식 GPT-4.1 모델 안내](https://developers.openai.com/api/docs/models/gpt-4.1)는 해당 모델을 계속 안내하고 있다. 현재 오류만으로 모델이 전체 서비스에서 폐지됐다거나 키가 무효라고 단정하지 않는다. 모델에 접근 가능한 프로젝트 키·권한 확인이 필요하다.

실제 실행 `.env`는 존재하며 workspace의 두 실습 `.env`와 같은 OpenAI 키를 사용하고 있었다. 별도 endpoint·organization·project routing도 설정되어 있지 않았다. 대체 제공자 키는 값이 비어 있어 사용 가능한 대체 경로를 확인하지 못했다. 확인 없이 기본 모델명을 바꾸지 않았다.

사용자가 자신의 키 사용을 재요청한 뒤 해당 파일의 키와 공식 API 주소를 SDK 인자로 직접 지정해 재확인했다. 실제 SDK 값의 일치 여부만 출력했으며 키·해시는 출력하지 않았다. 추가 최신 모델 두 개도 404였고, 별도의 Chat Completions 경로는 `PermissionDeniedError / HTTP 403 / model_not_found`로 실패했다. 총 11개 모델 후보에서 사용 가능한 교체 대상을 확인하지 못했다. 이 결과는 현재 키의 접근 문제를 조사할 근거이며 모든 OpenAI 모델의 서비스 종료를 뜻하지 않는다. [공식 오류 안내](https://developers.openai.com/api/docs/guides/error-codes)와 프로젝트 권한 확인이 필요하다.

키·권한과 실제 사용 가능한 모델을 확인한 뒤 재개한다. 같은 모델이면 동일 출력 경로의 `--resume`으로 pending Report부터 이어갈 수 있다. 다른 기본 모델로 교체하면 현재 CLI가 모델을 입력 identity로 취급하므로 명시적인 새 실행 기록으로 전환해야 한다. 완료된 이전 실행과 카운터·사용량을 지우지 않으며 모델 변경 범위를 기록한다. Report/Judge만 교체해 기존 관점 평가를 재사용하려면 그 혼합 실행도 별도 provenance로 기록하고 수정 피드백이 유실되지 않는 경로를 사용한다. 이전 PDF의 기간·기술 귀속 문제는 새 결과가 원문 검토와 Quality를 통과하기 전까지 해결됐다고 표시하지 않는다.

## 검증 범위와 구조 설명

- 명령과 테스트 범위는 JSON에 기록했다. 기존 stakeholder의 baseline 실패 8개는 이번 통과 범위 밖이며 전체 저장소 무결함을 주장하지 않는다.
- 새 PDF가 없으므로 수정 결과의 조판과 원문 정확도 검사는 미완료다. 이전 PDF의 시각 검사를 새 결과에 적용하지 않는다.
- saved RAG를 사용했다. 새로운 embedding/retrieval, Hit Rate@K·MRR, Judge calibration은 측정하지 않았다.
- LangSmith 연결 코드는 유지했다. 키가 없어 실제 동적 trace는 확보하지 않았다.
- [모델 구조와 실제 실행 방식](model-architecture.md)에 역할별 병렬 평가, TRL 연속 충족 판정, 상태·SHA 참조·체크포인트·예산과 수정 루프를 정리했다. 시각화는 구조 설명이며 실제 실행 trace가 아니다.
- 실행 출력·API 키는 새 커밋에 포함하지 않는다.
