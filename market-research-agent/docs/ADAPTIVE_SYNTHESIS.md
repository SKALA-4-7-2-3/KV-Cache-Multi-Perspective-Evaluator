# 자료 종합 평가 v1.5 — 구현 기준

## 목표

정상 입력의 기술별 여섯 항목을 실제 자료에 기반해 작성한다. 원문 수집 뒤 매 회차 평가하고, 남은 행에 대해 검색 범위와 평가 자료를 함께 확대한다. 정형 DECISIONS 문구는 모델 호출·검토 실패나 자료 부재에서만 사용하고 생성 방식을 표시한다.

| 수준 | 허용 자료 | 허용 판단 |
| --- | --- | --- |
| 0 | 확보한 웹 본문 | 선정 기술의 직접 근거 중심 |
| 1 | 웹 본문 + 등록 기술 요약 | 같은 기술군 자료를 이용한 조건부 평가, 모든 항목의 도입 추론 |
| 2 | 위 자료 + 검색 발췌 | 인접 시장의 대리 지표·부분 정보·가설을 명시한 잠정평가 |

모든 수준에서 인용 출처·대상 소유권·원문 일치·기준일 검사를 유지한다. 관련 제품의 채택/출시를 선정 기술의 실제 실적으로 바꾸지 않는다. 시장 수치의 부족한 지역·연도·정의를 생성하지 않고 원문 범위와 공백을 함께 제공한다. 서로 비교 불가능한 SW/HW 배수 성능은 직접 비교하지 않는다.

## 흐름

LangGraph: collect → synthesize → review → 다음 collect 또는 finish. 같은 수준에서 공급자 오류 재시도는 예산 내 최대 2시도. 수준 2 이후 실패한 행은 남은 LLM 예산 안에서 검색 없이 최대 두 번 재작성·재검토한다. 의미 검토를 통과한 행은 유지하며 실패한 행은 다음 수준에서 다시 평가한다. 기존 legacy analyst(추출/compose 주입) 계약은 별도 호환 경로로 유지한다. 실제 OpenAIAnalyst의 기본은 새로운 synthesis 계약이다.

인용 후보 생성에서 문장 종료 기호, 6~100단어, 필수 시장 키워드, 표 제외를 제거한다. 문자 길이에 따른 조각 분할과 관련도 순위는 토큰 예산을 위한 선택이다. 원자료는 캐시에 유지하고 대상별·항목별 자료를 공평하게 선택한다. 전역 claim 12개 제한은 새 경로에서 사용하지 않는다.

모델은 자료 ID를 선택하고 관찰·평가·조건·한계를 생성한다. 별도 검토 호출에서 원문 지원, 의미 관련성, 관계 범위, 조건 및 수치 해석을 확인한다. 코드의 필수 키워드가 의미 검토를 덮어쓰지 않는다. 근거와 판단 문장을 따로 보존한다.

## 완료 기준

- 자료 내용이 바뀌면 해당 자료를 사용하는 평가의 관찰·결론도 바뀐다.
- 키워드 없는 동의 표현, 표, 짧은 항목, 긴 문단이 후보에서 사라지지 않는다.
- 단계별 허용 자료·관계가 실제로 바뀌고 실패 항목만 보완한다.
- 모델 생성 평가와 정형 fallback을 generation_method로 구별한다.
- 오류가 발생해도 12행 제공, 오류·자료 한계 보존, 잘못된 출처는 검증 인용으로 승격하지 않음.
- 입력 JSON 4개와 기존 자료를 이용한 재현, 공급자 HTTP 모의 검사, 예산·재개·캐시 계약 검사.
- 새 외부 전송은 구체적 OpenAI/Tavily 승인이 확인된 경우에 실행한다. 이번 네 파일은 2026-09-22 사용자의 호출 승인을 확인했다.

## 구현된 계약과 한도

- 출력 버전 **0.6**. `observation`과 `judgment`를 분리한다. `generation_method=model_synthesis/verified_claim/deterministic_fallback`, `evaluation_level=0/1/2`를 기록한다. `model_synthesis`는 모델 응답 또는 명시된 fixture 제공자 응답을 사용했다는 의미이며 fixture에는 별도 경고가 나온다.
- 항목별 자료 묶음은 단계별 2/3/4조각을 우선 선택한다. 문장 길이/필수 키워드/마침표는 통과 조건이 아니다. 짧은 이용 조건은 본문으로 보존하고 제목·메뉴라는 구조 신호는 구분한다. 제목 조각은 본문보다 낮게 배치한다. 긴 문단은 1,400자 창으로 겹쳐 분할한다. 웹 본문·기술 입력·검색 발췌 슬롯을 배분하여 다수의 registry 조각이 웹 자료를 밀어내지 못하게 한다. 전체 원문은 캐시에 보존한다.
- 시장 수치의 정의·지역·연도가 불완전해도 원문 범위의 관찰과 공백을 함께 제공할 수 있다. 새 수치는 생성하지 않는다. 1.44 million과 144만 같은 번역 배율은 같은 값으로 검사한다.
- 매 단계 종합 1회 + 검토 1회가 기본이다. 직접 근거가 충분한 행은 재작성하지 않고 미해결/시나리오 행을 보완한다. 검토 호출 한도를 남긴다. 전체 기본 한도는 검색 18 / 원문 24 / LLM 10이다.
- `synthesis_records`에 원자료 ID·조각·모델 결정·검토 결과를 저장한다. 재개·오프라인 재검증 시 대상 소유권·기준일·원문 일치·관계·수치를 다시 검사한다. 기존 `verified_claim`과 새 종합 평가가 섞여 있어도 유효 행을 보존한다.
- 출력은 기술·항목별 고정 슬롯을 갖는다. 자료 ID는 해당 기술 소유 packet ID의 enum으로 제공하며, 비어 있지 않은 조건을 한 개 이상 요구한다. 자료가 없으면 슬롯은 null이고 다음 단계에서 보완한다. 출처가 같은 제목 한 줄만으로 미상용화·미채택·표준 부재를 단정하지 않으며, 서로 다른 데모의 수치·기준선을 합치지 않도록 별도 검토한다.
- 실제 본문 접근 실패·모델 오류·검토 기각은 남긴다. 정형 출력이 한 행이라도 있으면 실행 완료로 간주하지 않는다.
- 최초 검색 후보의 주제 검사, 공개 URL 검사, 잘못된 대상/미래 자료 배제, 토큰·호출 예산은 유지한다. 무제한 검색이나 모든 출처의 사실 인정을 의미하지 않는다.

## 현재 검증 한계

구조화 출력·Graph·저장·재개는 자동 검사와 실제 네 파일의 fixture 실행으로 검증했다. 승인된 실제 실행 두 번에서 자료 범위 혼동과 빈 조건을 발견해 항목별 출력 계약을 추가했다. 최종 계약은 자동 검사 통과, 추가 모델 품질 실행은 별도 승인 대기다. 시험 결과를 통합 전달본으로 채택하지 않았으며 상세 기록은 market_agent/LIVE_VALIDATION.md를 따른다.
