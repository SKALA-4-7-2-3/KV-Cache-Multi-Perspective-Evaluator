# 시장 평가 12항목 완성 설계 v1.4

> v1.4 구현 이력입니다. 현재 모델의 자료 종합 평가와 단계별 허용 기준은 [v1.5 설계](ADAPTIVE_SYNTHESIS.md)를 따릅니다.

## 수용 기준

정상 파싱된 두 기술 입력은 여섯 기준씩 총 12행을 전달한다. 최종 행의 verdict와 basis는 unknown으로 남기지 않는다. 검증된 평가는 보존하고, 부족한 항목에는 관련 자료를 포함한 잠정 판단 또는 기술 시나리오를 제공한다. 자료·처리의 한계를 숨기거나 시장 실적을 만들지 않는다.

## 조사 범위 확대

| 단계 | 조사 범위 | 허용 자료와 처리 |
| --- | --- | --- |
| 0 | 선정 기술 | 논문, 공식 구현·제품 단서. 약어가 같은 다른 제품은 제외 |
| 1 | 같은 기술군 | KV 양자화·추론 SW, CXL 메모리 풀링. 목적별 자료와 공식 문서 |
| 2 | 인접 시장 | AI 추론·GPU 인프라, AI 서버·분산 메모리. 업체·산업 분석·사례도 참고자료로 수용 |
| 전달 완성 | 기술 전제와 도입 시나리오 | 검증 주장과 별개로 모든 항목의 판단·조건·참고자료 제공 |

각 보완 단계는 시장/가치, 표준/생태계, 제품화/채택의 세 목적을 두 기술에 번갈아 배정한다. 작은 예산에서는 최초 검색에 없던 목적을 우선한다. 검색어는 중복 실행하지 않는다. 키워드는 인용 후보의 우선순위에 사용하며, 키워드가 없다는 이유만으로 추출 슬롯을 닫지 않는다.

JSON 기본 한도는 재시도 포함 검색 18 / 원문 24 / LLM 10회다. 통상 검색은 최초 2 + 보완 6 + 보완 6회이며 잔여 한도는 오류 재시도를 허용한다. 원문은 누적 6 / 14 / 24까지 단계적으로 사용한다. 사용자·부모의 더 작은 한도와 MD 입력의 명시 한도를 지킨다. 무한 재시도는 하지 않는다.

## 전달 계약 0.5

| evaluation_mode | 의미 | 최종 verdict | 신뢰도 |
| --- | --- | --- | --- |
| grounded | 기존 인용·주장·의미 검사를 통과한 평가 | conditional 등 기존 유효 판정 | 사실/동일 대상은 high, 조건부 추론은 medium |
| provisional | 관련 원자료·검색 발췌·검증된 보조 정보를 이용한 도입 판단 | provisional | low |
| scenario | 기술 조사 입력의 전제를 활용한 도입 시나리오 | provisional | low |
| research_plan | 자료도 기술 설명도 부족할 때의 항목별 조사·의사결정 계획 | provisional | low |

`provisional` 행은 기준별 결정 규칙으로 작성한다. 통계나 고객 실적을 자동 추정하지 않는다. 예를 들어 시장 규모에는 공략 고객·시장 산정 방법을, 제품화에는 구현·라이선스·지원 조건을, 채택에는 PoC 대상과 확대 조건을 명시한다. 데이터가 없는 수치형 TAM, 가격, 고객 수는 생성하지 않는다.

- `citations`: 검증된 주장만 유지한다.
- `supporting_materials`: evidence_id, 원문 quote, locator, review_status, reason을 보존한다. 원문 참고 / 기술 입력 요약 / 검색 발췌 / 추적용·판정 제외를 구분한다.
- 항목별 원문 참고 최대 2개와 기술 전제 1개를 제공한다. 기준일 이후·본문 실패·대상 불일치 자료는 제품화 행의 추적 목록(최대 6개)에 표시하고 판단에는 쓰지 않는다. 전체 자료는 내부 캐시에 남는다.
- 기존 conditions/gaps와 조사·검토 이력은 유지한다. 보고서에 실행 상태와 항목별 처리 한계가 나온다.
- `status`와 `technology_status`: 모든 행이 grounded면 completed, 잠정/시나리오가 포함되면 provisional. 치명적 실행 실패의 최상위 status는 failed다.
- `execution_status`: 실제 처리 completed/partial/failed. 문서 12행 작성 여부와 구분한다. CLI 종료 코드 0/3/2는 기존과 같다.
- `progress.delivery_coverage`: 평가 방식별 개수. 재검증 시 다시 계산한다.
- 원문 접근·모델 호출 실패가 있어도 파싱된 입력에서 12행은 제공한다. 입력 계약·해시 자체가 잘못된 경우에는 실행을 중단한다.
- 부모 재실행에서 provisional을 검증 Claim으로 복원하지 않는다. 내부 `analysis`는 검증 흐름을, `result.assessments`는 전달 완성 결과를 보관한다.

## 보고서

최종 산출물은 `market_handoff.md` 하나다. 두 기술의 여섯 시장 항목, 평가 방식·신뢰도·조건, 검증 인용, 재검토용 자료를 포함한다. 회의 내용, 다른 역할의 평가, 디버그 원문은 넣지 않는다. 같은 URL의 직접 발췌는 전체 보고서 합산 25단어 이내로 제한하며 나머지는 원문 위치로 찾는다.

## 검증

- 전달 완성 계약: 빈 평가, 기술 요약만 존재, 모델 오류, 부적격 출처, 기존 유효 평가 보존.
- 3단계 검색: 모든 목적 배정, 검색 중복 방지, 한도 준수, 약어 충돌 제외.
- 부모 재개: 잠정 결과가 사실 근거로 승격되지 않음, 오류/사용량 보존.
- 보고서: 12행과 참고자료, 실제 처리 한계, 상태 표시.
- 실제 첨부 JSON 네 개와 과거에 수집한 원자료를 재사용하여 12/12행을 검증한다. 새 외부 호출 여부는 LIVE_VALIDATION에 별도로 기록한다.

이 문서가 기존 v1.3 설계의 unknown 최종 전달 정책과 기본 JSON 예산을 대체한다. v1.3 이하의 기록은 당시 결과를 설명하는 이력이다.
