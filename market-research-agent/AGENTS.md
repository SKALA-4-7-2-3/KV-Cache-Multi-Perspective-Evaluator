# 시장조사 프로젝트 작업 규칙

## 수정 완료 후 자동 커밋·푸시

사용자는 2026-09-22에 **Codex가 수정 작업을 마치면 검증 후 자동 커밋·푸시**하도록 요청했다. 이 폴더의 향후 작업에도 이 선호를 적용한다.

- 대상 저장소: `SKALA-4-7-2-3/KV-Cache-Multi-Perspective-Evaluator`
- 원격: `origin`
- 대상 브랜치: `feat/market-agent`
- 적용 시점: 사용자가 요청한 수정 작업을 완료하고 해당 변경의 검증을 마쳤을 때.

### 진행 순서

1. 저장소·브랜치·기존 변경 상태를 확인한다. 기존 사용자 변경과 다른 작업의 파일을 구분한다.
2. 변경에 필요한 테스트와 검토를 수행한다. 문서만 바꾼 경우에는 내용과 diff 형식을 확인한다.
3. 이번 작업에서 완료한 파일만 명시적으로 스테이징한다. 실제 API 키, `.env`, 가상환경, 캐시·원문 수집 자료, 개인 파일은 제외한다. 기존 `.gitignore`를 유지한다.
4. `git diff --cached --check`와 스테이징 내용을 확인하고 변경 목적이 드러나는 메시지로 커밋한다.
5. 별도 사용자 확인 없이 `git push origin HEAD:feat/market-agent`를 실행한다. 원격 커밋과 로컬 커밋의 일치를 확인하고 결과를 보고한다.

검증이 실패하면 먼저 수정한다. 브랜치·원격이 위 대상과 다르거나 충돌·인증·네트워크 문제로 푸시할 수 없으면 상태와 남은 작업을 알린다. 강제 푸시, 사용자 변경 삭제, main 병합은 이 규칙의 자동 작업에 포함하지 않는다. 사용자의 이후 명시적 지시를 우선한다.
