# JSON 입출력 전환 검증 기록

검증일: 2026-09-22. 코드 버전: 0.2.0. 기본 공통 JSON 버전: 1.0. 입력 paper_analysis 버전: 1.1.0.

## 통과한 검증

- 전체 테스트 372개 통과. 기존 Markdown 연구 그래프의 회귀 테스트와 신규 JSON 계약, CLI, 상위 State 연결 테스트를 함께 실행했다.
- Ruff 검사 통과.
- wheel 및 source distribution 빌드 통과.
- 제공받은 실제 논문 JSON 두 개를 읽고, 25개 논문 근거의 ID, 발췌 및 원본 chunk 메타정보가 보존되는 것을 확인했다.
- `examples/output.fixture.json`은 실제 입력 형태로 LangGraph를 실행한 오프라인 결과다. status=partial, execution_status=completed, evidence_status=limited, 논문 기반 예시 주장 2개, 논문 근거 25개다. 실제 이해관계자 발언이나 실제 모델 조사 결과가 아니다.
- 최초 자연어 요청과 추가 정보, 복수 도메인의 전달을 검증했다. 논문 scope를 사용자 요구로 바꾸지 않는다.
- 근거 ID 충돌, 끊긴 인용, JSON 중복 키, 잘못된 자료형, 요청 누락, 별도 요청의 입력 크기 초과를 검증했다.
- 의미 검토 실패 시 주장과 요약을 공개하지 않고, 거절된 주장에 의존하는 시사점도 제외한다.
- 상세 결과에 미등록 주장을 추가하거나 출처를 바꾸면 출력 검증에 실패한다. 누적 사용량과 남은 한도의 모순도 검출한다.
- 상위 회차가 바뀌어도 누적 사용량을 유지하며, 입력 오류가 생겨도 기존 실행 ID, 회차 및 유효한 누적 사용량을 유지한다.
- 상위 회차별로 신규 웹 근거 ID를 구분해 다른 원문에 같은 ID를 재사용하지 않는다.
- 기존 부모 State의 다른 역할 결과를 변경하지 않고 이 역할의 변경분만 반환한다.
- 모델 인증 오류 시 오류 본문의 비밀값을 숨기고 후속 검색을 생략하는 처리를 모의 응답으로 검증했다.

## 실제 네트워크 실행

원본 Downloads 파일 두 개와 별도 request.json으로 실제 실행을 시도했다. 기존 환경 설정 파일을 명시적으로 사용했으며 키를 이 저장소로 복사하지 않았다.

첫 실행에서 모델 요청 2회가 실패했고, 웹 검색 2회와 원문 수집 2회가 수행되었다. 별도의 최소 구조화 호출 1회로 원인을 확인한 결과, 모델 API 응답은 HTTP 401 / invalid_api_key였다. 검증된 최종 분석 주장은 생성되지 않았으며 결과는 failed로 반환되었다. 이 실행은 새로운 입력이 파싱되고 웹 도구에 연결되는 것을 확인했지만, 실제 모델을 포함한 전체 분석의 성공 검증은 아니다.

이 진단 이후 인증 오류에서 후속 호출을 멈추는 처리를 추가하고 테스트했다. 실패한 실제 실행의 이력을 성공 결과로 다시 표시하지 않았다. 실제 실행 출력은 `outputs/`에 있으며 Git에서 제외한다.

이후 Git용 폴더에 사용자가 설정한 로컬 `.env`의 OpenAI 키로 다시 실행했다. 이 실행에서는 해당 파일의 설정이 사용되도록 실행 프로세스에 상속된 관련 환경변수를 제외했다. 제공된 논문 예제 JSON 두 개와 request.json으로 실제 모델 호출 5회를 수행했고, `execution_status=completed`, `evidence_status=limited`, `status=partial` 결과를 생성했다. 출력은 `StakeholderOutput` 검증을 통과했다. 당시 로컬 Tavily 키가 없어 검색과 원문 수집은 각각 0회였으며, 외부 검색 미설정 오류와 신규 웹 근거가 없다는 사실을 결과에 기록했다. OpenAI 연결은 확인되었지만 새 로컬 설정으로 외부 조사까지 포함한 전체 실행은 추가 검증이 필요하다.

### 두 키를 설정한 후 실행

같은 로컬 `.env`에 Tavily 키를 추가한 후 `stakeholders-git-web-20260922` 실행을 수행했다. Git에 포함할 두 논문 예제는 원본과 `paper.source_path`만 다르고 나머지 내용이 동일함을 확인했다. 모델 호출 5회, 검색 6회, 원문 수집 5회를 수행했으며 API 및 실행 오류는 기록되지 않았다. 결과는 `mode=live`, `execution_status=completed`, `status=partial`, `evidence_status=unavailable`이다.

실제 출력 `outputs/stakeholders-git-web.json`은 `StakeholderOutput` 검증을 통과했다. 기존 논문 근거 25개와 웹 근거 5개를 보존했고, 웹 자료의 URL, 요청 URL, 검색어, 조회일, 수집 본문, 발췌 SHA256 및 출처 검토 기록을 확인했다. 발췌 해시는 내용과 일치하며 실제 키 값은 출력에 없었다. 발행 주체와 발행일은 수집 메타정보에서 확인되지 않아 미표기로 남았다.

다만 최종 분석 품질 검증은 통과하지 못했다. 웹 자료 3개는 모델이 관련성 부족으로 제외했고, 보완 검색에서 얻은 2개는 모델의 출처 평가가 누락되어 보류되었다. 최종 초안의 주장 2개가 사용 불가 출처를 인용해 제외됐고, 공개된 주장은 양쪽 기술 모두 0개이며 참고문헌도 0개다. 보류된 자료를 자동 승인하거나 수집한 출처를 실제 인용 참고문헌으로 바꾸지 않았다. 수집 이력 5개는 `new_evidence`와 `source_audits`에서 확인할 수 있다.

이 실행은 두 API와 실제 전체 실행 경로의 동작을 확인한 것이며, 보고서에 사용할 분석 내용 확보를 확인한 것은 아니다. 출처 검토 누락을 보완하고, SW 계열 자료까지 균형 있게 찾을 수 있도록 검색 전략을 점검해야 한다. 결과의 `unavailable`을 공개 자료 전체에 이해관계자 근거가 없다는 의미로 해석하면 안 된다.

## 남은 통합 범위

- 팀 전체 Graph와 현재 feat/review-agent 규격에 대한 종단 간 통합 테스트는 수행하지 않았다. 새 설계와 팀 검증 코드의 계약 차이는 INTEGRATION.md에 명시했다.
- 이 에이전트는 기술의 종합 적합성 판정이나 승자 선정을 수행하지 않는다. 공통 criterion의 judgment는 unknown이며, 실제 관찰과 적용 조건 및 출처를 제공한다.
- 입력 논문의 원문 전체를 다시 RAG하거나 실험을 재현하지 않았다. 제공된 발췌의 생략 및 upstream 서지 정보 누락을 결과에 남긴다.
- 설계서와 입력에 기록된 임베딩 모델의 차이는 upstream 확인 사항으로 보존했다.
- 상위 Graph의 병렬 reducer, 체크포인트 및 전체 보고서 생성은 팀 통합 계층의 책임이다.

## 운영 조직 중심 수정 후 빠른 실행 확인

사용자 요청에 따라 기본 JSON 분석 대상을 도메인별 운영 조직 하나로 통일하고, 실제 외부 반응 확보 중심에서 기대 이익, 부담과 우려, 도입 검토 조건 중심으로 변경했다. 기존 공통 JSON 필드와 논문 원본은 유지했다. SW/HW 기술 계열 검색 후보를 함께 허용하고, 검토 누락 ID를 보완 대상으로 전달하며, 같은 자료의 완료된 출처 평가를 보존한다.

수정 중 실행한 operator-impact와 operator-impact-v2는 중간 결과다. 최종 빠른 실행은 프롬프트 1.2.2의 operator-impact-v3-20260922이며 출력은 outputs/operator-impact-v3.json이다. OpenAI 모델 호출 5회, 웹 검색 4회, 원문 수집 8회와 내부 보완 1회를 수행했다. 운영 조직은 1개, 생성된 결과는 SW 5개와 HW 5개다. 프로그램의 의미 검토를 거쳐 JSON이 출력됐으나 이것만으로 모든 판단의 타당성이 검증됐다고 보지 않는다. 특히 일부 문장이 연결된 인용 범위보다 강할 수 있어 추가 검토가 필요하다.

결과는 execution_status=completed, evidence_status=limited, status=partial이다. 웹 자료 8개 모두 출처 검토가 미완료되어 오류와 한계로 기록됐고 최종 인용에는 사용되지 않았다. 참고문헌은 두 입력 논문의 근거 위치 9개이며 독립 문서 9편이 아니다. 결과를 외부 조사가 완료된 보고서로 취급하면 안 된다.

사용자가 결과 확인을 우선하고 테스트를 나중에 하도록 요청하여 이후 추가 테스트 실행은 생략했다. 마지막 provider 검토 형식과 검색 보완 변경을 포함한 최종 코드의 전체 회귀 테스트는 아직 실행하지 않았다. 키, 실제 출력과 내부 진단은 Git에서 제외하며 커밋과 푸시는 하지 않았다.

## 논문명 직접 언급 조건 제거 후 빠른 실행

기본 JSON 실행에서 관련 웹 자료의 사용 조건을 본문 주제 중심으로 바꿨다. KV 압축 또는 CXL 메모리 운영 설명은 대상 논문명을 언급하지 않아도 `limited/family`로 사용한다. 이 결정은 주제와 메타정보 확인이며 신뢰성, 독립성 또는 실제 도입의 인증이 아니다. 주장별 발언 귀속과 인용 대조는 유지한다. 기존 Markdown 경로는 변경하지 않았다.

첫 실행 operator-family에서는 페이지 이동 링크의 URL에 포함된 주제 단어를 잘못 근거로 인정했다. 이를 발견하여 링크의 목적지, 제목과 짧은 메뉴를 제외하고 보이는 본문으로 관련성을 확인하도록 수정했다. operator-family-v2-20260922는 프롬프트 1.3.1-family-evidence로 다시 수행한 실제 실행이다. 출력은 outputs/operator-family-v2.json이다.

모델 5회, 검색 6회, 원문 수집 4회, 내부 보완 1회로 SW 결과 5개와 HW 결과 3개를 생성했다. execution_status=completed, evidence_status=limited, status=partial이며 실행 오류는 없다. NVIDIA NVFP4 기술 블로그와 KV 압축 연구 발표 영상 등 SW 계열 외부 자료 2개를 실제로 인용했다. HW 후보 2개는 수집 범위에서 사용 가능한 본문을 확보하지 못해 제외했고, HW 결과는 전달된 논문 근거에 의존한다. 이는 CXL 관련 자료 자체가 부적합하거나 존재하지 않는다는 뜻이 아니다.

결과는 검토용 초안이다. 모델의 의미 검토가 통과했어도 HW의 'HBM급 대역폭', '32TB 이상' 같은 표현은 연결된 인용이 지지하지 않으며, 에뮬레이션 성과를 운영 성과처럼 표현한 부분도 남아 있다. SW의 why-distortion 표현과 일부 조건의 과도한 단정도 정리가 필요하다. 외부 자료를 사용하는 경로와 JSON 출력 생성은 확인했지만 최종 보고서의 사실 검증 완료로 해석하면 안 된다. 자동 테스트와 추가 빌드는 사용자 요청에 따라 실행하지 않았다.

## 외부 자료 제한 완화 및 반복 없는 실행

사용자의 시간 제약에 맞춰 기본 JSON 경로에서 검색 후보의 고정 키워드 조합 검사를 제거했다. 본문이 있는 후보는 limited로 분석 단계에 전달하고, 출처를 귀속한 발언뿐 아니라 관련 기술 계열의 조건부 운영 분석에도 활용한다. 알 수 없는 관련성은 unknown으로 유지하며 본문 확보를 신뢰성 인증으로 표시하지 않는다. 근거 ID, 인용 대조와 모델 의미 검토는 유지한다.

operator-quick은 외부 자료 8개를 수집했지만 모델이 최종 근거에 연결하지 않은 중간 출력이다. 관련 본문이 있을 때는 실제 웹 근거 ID를 결과에 연결하도록 프롬프트를 보완했다. 최종 빠른 실행 operator-quick-v2-20260922는 프롬프트 1.4.1-broad-web-reference이며 outputs/operator-quick-v2.json에 저장했다. 이 실행에만 repair_limit=0, llm_limit=3을 적용했고 기본 보완 한도는 변경하지 않았다.

최종 실행은 모델 3회, 검색 4회, 수집 8회, 내부 보완 0회다. SW 결과 5개, HW 결과 4개와 실제 인용된 외부 자료 4개를 출력했다. SW에는 LMDeploy 문서 및 KV 압축 발표 영상, HW에는 DataIntelo 및 Patsnap 자료를 참고자료로 사용했다. execution_status=completed, evidence_status=limited, status=partial이며 실행 오류는 없다.

출력은 초안이며 모든 주장과 출처의 신뢰성이 확정된 결과는 아니다. 예를 들어 HW C007의 전력 절감 및 대역폭 수치가 선택된 인용에 없고, C009의 비용 최적화 인용은 장애 대응에 관한 주장 전체를 지지하지 않는다. 모델 의미 검토가 이런 문제를 놓친 상태이므로 해당 문장들은 최종 보고서에 그대로 사용할 수 없다. 이번 확인은 수집 제한 완화와 외부 근거 연결 및 JSON 출력 생성에 한정한다. 추가 자동 테스트, 빌드, 커밋과 푸시는 수행하지 않았다.
